## 本讲路线图

- 全文扫描的问题 → 词项与文档的关系 → 倒排表及位置信息 → 索引构建、扩展与压缩 → 检索质量评价。

## 1. 从全文扫描到倒排文件 [S1–S6]

倒排文件索引（Inverted File Index）按“词项 → 出现它的文档”组织数据，使检索无需每次逐篇扫描全文。[S1–S3]

### 1.1 逐篇扫描与词项—文档矩阵 [S2–S4]

**重要性：A · 必须掌握**

查询 `Computer Science` 时，最直接的方法是逐页搜索这个字符串；文档多时，每次查询都要重复处理全部内容。词项—文档关联矩阵（Term-Document Incidence Matrix）改为预先记录某词是否出现于某篇文档：行是词项，列是文档，元素为 $0$ 或 $1$。[S2–S4]

S4 的四篇文档中，`silver` 的位向量是 `1010`，`truck` 的位向量是 `1011`。按位与得到

```text
silver AND truck = 1010 AND 1011 = 1010
```

因此同时包含两词的是文档 1 和 3。这个表示法让布尔与查询很直观，但若词汇量和文档量都大，完整矩阵会包含大量零。[S4]

### 1.2 倒排表与文档频率 [S5]

**重要性：A · 必须掌握**

索引（Index）是根据给定词项定位文本的机制。倒排文件为每个词项维护出现位置的列表；最基础的形式只保存包含该词的文档编号，称为倒排表（Posting List）。词项到列表的入口集合是词典（Dictionary）。[S5]

对 S4 的样例，`silver → {1,3}`、`truck → {1,3,4}`，所以求交仍得 `{1,3}`。与完整矩阵相比，只保存出现过的文档编号，可避免为大量零项分配空间。[S4–S5]

课件表格写作 `<Times; Documents>`。其中 `silver` 对应 `<2; 1,3>`，虽然文档 3 中 `silver` 出现两次；这里的 `Times=2` 实际是文档频率（Document Frequency, DF），即**包含该词的文档数**，不是整个集合里的词次。[S5–S6]

### 1.3 位置倒排表与多词查询 [S6]

**重要性：A · 必须掌握**

若要找出并高亮含查询词的句子，可在倒排项中额外保存文档内词位。例如 `silver` 在文档 3 的位置为 `(3;3,7)`，表示该文档中第 3 和第 7 个词是 `silver`。词位信息能支持短语查询、邻近查询和结果片段定位。[S6]

### 核心原理

> 先按倒排表求出可能包含所有查询词的文档，再用位置列表核实词序或距离，避免扫描无关文档。

例如查询两个连续词 `A B`：先对两词的文档编号集合求交，仅保留共同文档；再在每篇候选文档内检查是否存在 `A` 的位置 $p$ 与 `B` 的位置 $p+1$。只求文档交集只能保证“同篇出现”，不能保证“连在一起”。[S6]

> **解释补充：** S6 的位置表回答了“怎样打印并高亮句子”的问题，但词位本身还不足以恢复原句；实际展示时还需要保留或读取原文，并把词位映射回句子或字符偏移。

讲者备注指出，多词 `AND` 查询宜从文档频率最小的词项开始求交，较小的中间结果通常减少后续比较。[S6，讲者备注]

## 2. 索引生成与受限内存处理 [S7–S10]

索引构建从逐文档分词开始，依次处理词形、停用词、词典查找和倒排项写入；内存不足时需要分块落盘并归并。[S7–S10]

### 2.1 基本索引生成器 [S7]

**重要性：A · 必须掌握**

### 核心原理

> 遍历每篇文档的词项：词不在词典时先加入词典，然后定位它的倒排表、写入当前文档或位置，最终把索引持久化。

```text
for each document D:
    for each analyzed term T in D:
        if T is absent from dictionary:
            insert T into dictionary
        locate posting list of T
        add the occurrence information for T in D
write the inverted index to disk
```

课件把词法分析（Token Analyzer）、停用词过滤（Stop Filter）、词汇扫描、词典插入和内存管理列为生成过程的组成部分。[S7]

> **解释补充：** 若目标倒排表只保存**唯一的文档编号**，同一词在同一文档反复出现时不能重复插入文档号；应合并成一个文档项，并在其下维护出现次数或位置。课件伪代码中的“每读一词插入一个节点”是生成流程的简写。[S5–S7]

### 2.2 词形归一与停用词 [S8]

**重要性：B · 重点理解**

词干提取（Stemming）把不同词形尽量归并到统一形式，例如 `process / processing / processes / processed → process`。课件也把 `says / said / saying → say` 作为归一示例。建立索引与查询时需使用一致的词形处理规则，否则查询词可能无法命中已归一的词项。[S8]

停用词（Stop Words）是高频而区分度较低的词，如 `a`、`the`、`it`；过滤它们可减少索引规模。是否过滤取决于查询需求：若系统要支持精确短语，常见词的位置有时仍重要。[S8]

### 2.3 词典查找结构 [S9]

**重要性：B · 重点理解**

访问词项时，课件给出搜索树（如 B 树、B+ 树、Trie）和哈希（Hashing）两类词典组织方式，并提出比较其优缺点。[S9]

> **解释补充：** 哈希适合词项的平均常数时间精确查找，但不直接提供有序遍历；搜索树按键排序，便于范围或前缀相关操作，但单次查找通常需沿树高进行。实际性能还取决于碰撞、缓存、磁盘页布局及是否使用 Trie。

### 2.4 内存不足时的分块索引 [S10]

**重要性：A · 必须掌握**

### 核心原理

> 内存中的临时索引满时先排序并写成一个磁盘块，继续处理后续文档；最后对有序块进行归并，形成完整倒排索引。

1. 顺序读文档、分析词项，在内存中构建当前块索引。
2. 内存用尽时，把块按词项及倒排项顺序排序，写成 `BlockIndex[i]`，释放内存。
3. 所有文档处理完后，对磁盘上的有序块归并；相同词项的倒排项合并并保持文档编号有序。[S10]

讲者备注明确要求在写磁盘前先排序，使归并效率更高。内存块容量越大，块数通常越少，但占用内存更多。[S10，讲者备注]

## 3. 规模扩展、更新与压缩 [S11–S14]

文档集合继续增长时，索引可以按词项或文档分布到多节点；文档更新和空间压力又带来辅助索引与压缩技术。[S11–S14]

### 3.1 分布式索引的两种切分方式 [S11]

**重要性：B · 重点理解**

词项切分（Term-Partitioned Index）把不同词区间交给不同节点，如 `A–C` 与 `X–Z`；查询需要访问包含查询词的节点。文档切分（Document-Partitioned Index）把不同文档编号区间交给不同节点，如 `1–10000` 与 `10001–20000`；每个节点为自己的文档子集建索引。[S11]

> **解释补充：** 词项切分便于定位某词的倒排表，但多词查询可能跨节点；文档切分可在各节点上并行处理同一查询，最后合并局部结果。二者的网络与负载代价依查询分布而变。[S11]

### 3.2 动态索引 [S12]

**重要性：B · 重点理解**

文档不断进入时，已有词项的倒排表要追加文档，新词项要进入词典；文档删除也要反映到检索结果。课件用主索引（Main Index）和辅助索引（Auxiliary Index）示意增量更新，并提出何时重建、怎样删除文档的问题。[S12]

> **解释补充：** 一个可行实现是让新文档先进入较小的辅助索引，查询同时读取主索引和辅助索引，再定期合并；删除可先记录待删除文档号，并在合并时清理。这是对图示问题的实现补充，具体合并阈值不由课件给定。

### 3.3 词典与倒排表压缩 [S13]

**重要性：B · 重点理解**

词典中相邻词可连接存储以减少重复的定长槽位开销，课件展示了把多个词拼接保存的示意。倒排表的文档编号一般递增，可只保存首个编号与后续差值：

```text
文档编号： 2, 15, 47, …, 58879, 58890, …
间隔值：   2, 13, 32, …, 11, …
```

这叫间隔编码（Gap Encoding）；多数间隔比绝对文档编号小，因此可以再用变长整数编码减少位数。[S13]

### 3.4 截断检索 [S14]

**重要性：B · 重点理解**

阈值截断（Thresholding）有两种示例：只取按权重排在前 $x$ 的文档，或按频率排序后只处理一部分查询词。它减少处理量，却可能漏掉相关结果。只取前 $x$ 文档不能保证完整布尔查询；只处理部分查询词则改变了原查询约束。[S14]

## 4. 检索系统的评价 [S15–S18]

检索系统既要衡量索引与查询速度，也要衡量返回结果是否真正符合信息需求。[S15]

### 4.1 性能、表达能力与相关性 [S15]

**重要性：B · 重点理解**

工程指标包括每小时索引文档数、查询延迟随索引规模的变化、索引占用空间，以及查询语言能否表达复杂需求并高效执行。相关性评价还要观察返回结果是否令用户满意；“找得快”和“找得准”是不同维度。[S15]

### 4.2 精确率与召回率 [S16–S17]

**重要性：A · 必须掌握**

相关性评价需要基准文档集合、基准查询集合，以及每个“查询—文档”对是否相关的判定。令 `RR` 为被检索且相关的文档数，`IR` 为被检索但不相关的数，`RN` 为未被检索但相关的数，`IN` 为未被检索且不相关的数。[S16]

### 核心原理

> 以“已经返回的结果”和“所有真正相关的文档”为两个不同分母，分别衡量结果纯度和覆盖程度。

$$\boxed{\text{精确率（Precision） }P=\frac{RR}{RR+IR}},\qquad
\boxed{\text{召回率（Recall） }R=\frac{RR}{RR+RN}}.$$

精确率高表示返回结果中垃圾少；召回率高表示相关文档漏得少。例如 `RR=8, IR=2, RN=12`，则 $P=8/10=0.8$，$R=8/20=0.4$：前十条看起来较准，但还有十二篇相关文档没找到。[S16–S17]

> **解释补充：** 数值例子用于说明分母不同，不是课件表格中的实测数据。阈值提高时通常能减少不相关结果，却可能增加漏检；S17 的曲线示意这种取舍，不能保证任意方法都沿同一条曲线变化。

### 4.3 改进相关性的开放讨论 [S18]

**重要性：C · 了解即可**

S18 把“如何提高搜索结果相关性”留作讨论题。复习时可以从查询词处理、匹配证据、排序权重与评估数据集四方面思考，但具体方法及其效果需要另外设计和验证。[S18]

## 本讲总结

- 倒排索引把词项映射到文档列表，避免每次查询扫描全文。[S2–S5]
- 词项—文档矩阵的按位与对应 `AND` 查询；倒排表求交只处理实际出现的文档号。[S4–S6]
- 位置信息支持短语与高亮；S5–S6 的 `Times` 是文档频率，不能误当词次。[S5–S6]
- 索引生成需分析词形、维护词典和倒排表；内存不足时先排序分块再归并。[S7–S10]
- 分布式切分、动态辅助索引、间隔编码与截断分别应对规模、更新、空间和查询代价。[S11–S14]
- 精确率看结果纯度，召回率看相关文档覆盖率。[S15–S17]

## 结构与适用条件速查

| 结构 / 方法 | 核心作用 | 代价或限制 | 来源 |
|---|---|---|---|
| 全文逐篇扫描 | 不预建索引 | 每次查询重复扫描集合 | S2–S3 |
| 词项—文档矩阵 | 布尔运算可按位执行 | 大规模矩阵稀疏 | S4 |
| 倒排表 | 只保存出现词项的文档 | 需维护词典和有序列表 | S5–S7 |
| 位置倒排表 | 支持短语与高亮 | 增加索引空间 | S6 |
| 分块排序归并 | 内存不足时建索引 | 产生磁盘写入与归并代价 | S10 |
| 文档切分 / 词项切分 | 多节点分担索引 | 查询路由和结果合并 | S11 |
| 间隔编码 | 压缩递增文档号 | 解码时需累加间隔 | S13 |
| 阈值截断 | 限制查询处理量 | 可能丢失相关结果 | S14 |

## 易错点

- `silver → {1,3}` 里的 `2` 是包含该词的文档数，文档 3 中重复出现两次不改变这个数字。[S5–S6]
- 两词出现在同一文档，只满足 `AND`；要确认相邻短语，需检查词位差。[S4–S6]
- 建索引时的分词、词形归一和停用词策略必须与查询处理保持一致。[S7–S8]
- 分块索引先排序再写盘，才能有效归并同词项的列表。[S10，讲者备注]
- 只返回前 $x$ 条不保证完整布尔结果，也可能降低召回。[S14]
- 精确率分母为所有**已检索**文档，召回率分母为所有**相关**文档。[S16]
